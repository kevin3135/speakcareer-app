# SpeakCareer Design Principles

## Design Identity

SpeakCareer is a career English practice app with the motivation of a learning game and the confidence of a premium professional tool.

It should feel:

- fun but professional
- simple but not empty
- colorful but not childish
- warm but not silly
- structured but not academic
- motivating but not manipulative
- fast enough for daily use
- polished enough for a paid product later

Working design theme: **Career Arcade**

The app should feel like unlocking better workplace conversations one short lesson at a time.

## Core Visual Direction

### Color

- Use emerald as the active learning color.
- Use gold for XP, rewards and celebration.
- Use ink for strong typography.
- Use soft blue for AI feedback and corrections.
- Use light cool backgrounds instead of flat grey.
- Avoid one-note green-only screens.

### Typography

- Use rounded, friendly typography for headings and CTAs.
- Keep body text calm and readable.
- Avoid too many uppercase labels.
- Make the active action larger than explanatory copy.
- Use short labels: `Start`, `Check`, `Save`, `Continue`.

### Layout

- One screen equals one job.
- One primary CTA per screen.
- First viewport must show the next action.
- Optional tools should be collapsed.
- Use visual sequence before explanation.
- Avoid walls of text.

### Motion And Rewards

No heavy animation is required yet, but the UI should be prepared for:

- XP pop after saving
- lesson node unlock
- streak confirmation
- correction saved to mistake bank
- next lesson highlight

## Product Principles

### 1. App-Led, Not User-Led

The app should take charge. A beginner should not have to choose between Home, Practice, Roleplay and Progress. The app chooses the next useful step.

Design rule:

- Show one active lesson.
- Show locked next lessons.
- Hide browsing until after confidence is built.

### 2. English Foundation Before Career Complexity

Users should learn the basic sentence structure before career scenarios become complex.

Design rule:

- Teach `I + action + result`.
- Then apply it to Job Interview.
- Then unlock Meeting, Presentation, Sales and Small Talk.

### 3. Career Context Is The Brand

SpeakCareer is not a generic language game. Every visual and copy choice should point back to professional confidence.

Design rule:

- Use office, interview, meeting and presentation language.
- Avoid fantasy, animals, childish badges or school-like stickers.
- Make rewards feel like career momentum.

### 4. AI Coach Feeling

The AI should feel like a helpful coach, not a dashboard.

Design rule:

- Use short coach messages.
- Show corrections as "Better English".
- Use a consistent coach badge or bubble.
- Avoid technical scoring language in first-run flows.

### 5. Daily Habit Loop

The product should create a healthy daily loop:

1. Start one short lesson.
2. Answer one realistic prompt.
3. Get one useful correction.
4. Save for XP.
5. Unlock the next lesson.

Design rule:

- Never show five equal actions when one action is enough.
- Reward completion quickly.
- Make tomorrow's next step obvious.

### 6. Premium Simplicity

Premium does not mean more decoration. Premium means clear hierarchy, confident spacing and fewer decisions.

Design rule:

- Use fewer cards.
- Use stronger contrast for the active card.
- Make locked states elegant.
- Remove technical or internal notes from learner screens.

### 7. No Boring Grey Screens

Grey is allowed for borders and disabled states, but not as the personality of the app.

Design rule:

- Each major screen needs one strong branded visual area.
- Use muted surfaces only for secondary content.
- Reward, coach and correction states should have distinct color roles.

## Screen Rules

### Onboarding

- Ask one question at a time.
- Use coach bubble.
- Use progress bar.
- Continue button stays disabled until a choice is made.
- After selection, go straight into the first lesson.

### Learn

- Must look like a path, not a dashboard.
- One active node.
- Locked future nodes visible.
- Streak/XP small at the top.
- Primary CTA: start active lesson.

### Lesson

- Must teach one structure only.
- Needs interaction later, not just reading.
- Use one example.
- Continue to practice.

### Roleplay

- Conversation should be visually central.
- The answer box should appear early.
- Scenario and angle are options, not first-class decisions.
- Feedback should be one correction first, details later.

### Wins

- Celebrate progress.
- Show latest save.
- Show one mistake to fix.
- Hide full lists.

### Me

- Quiet settings only.
- No developer roadmap language.
- No integration status in the learner UI.

## Anti-Patterns

Avoid:

- full dashboards for beginners
- five equal buttons
- long explanatory cards
- technical implementation copy
- too many filter chips
- multiple CTAs above the fold
- grey-on-grey screens
- copying Duolingo's mascot, colors or exact path visuals
- copying Speak, ELSA, Praktika or Babbel branding

## Design North Star

In three seconds, the user should know:

1. what lesson they are on
2. what to do now
3. what they unlock next

If a screen fails that test, simplify it before adding features.
